
**Жизненный цикл ИС** – это модель создания и использования информационной системы. Он отражает различные состояния ИС, начиная с момента возникновения необходимости в этой информационной системе и принятия решения о ее создании и заканчивая полным изъятием информационной системы из эксплуатации.

**Модель ЖЦ** - структура, определяющая последовательность выполнения и взаимосвязи процессов, действий и задач, выполняемых на протяжении ЖЦ. Модель ЖЦ зависит от специфики ИС и условий ее создания и функционирования.

На практике чаще всего выделяют три основные модели жизненного цикла:
- каскадную;
- спиральную (эволюционную);    
- итерационную.

---
## Каскадная модель

**Каскадная модель** предполагает последовательное прохождение этапов разработки: следующий этап начинается только после полного завершения предыдущего. Обычно каждый этап заканчивается выпуском документации, достаточной для продолжения работы другой командой.

 ![[lifecycle_cascade.png]]

| Достоинства                                                                  | Недостатки                                                                          |
| ---------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| Однократное представление всех возможностей<br>(характеристик) системы       | Требования к объектам определены недостаточно четко                                 |
| Необходимость только единственной фазы перехода от<br>старой системы к новой | Система обычно слишком велика, чтобы все работы по ее созданию выполнять однократно |
|                                                                              | Предполагаемые скорые изменения в технологиях работ                                 |
|                                                                              | Возможные текущие изменения требований к системе                                    |
|                                                                              | Ограниченность ресурсов, например средств или персонала                             |
|                                                                              | Промежуточный продукт может быть непригоден для<br>использования                    |

## Спиральная модель

**Спиральная модель** делает основной акцент на ранних этапах разработки - анализе, проектировании и оценке рисков. На каждом витке создается прототип или версия системы, уточняются требования, оцениваются риски и планируются работы следующего цикла.

Главная идея этой модели - постепенно уточнять проект и как можно раньше показывать заказчику работоспособный результат, чтобы вовремя корректировать требования и решения.

 ![[lifecycle_spiral.png]]

| Достоинства                                                                             | Недостатки                                          |
| --------------------------------------------------------------------------------------- | --------------------------------------------------- |
| Наиболее реально отображает процесс разработки ПО                                       | Повышенные требования к заказчику                   |
| Позволяет учитывать риск на каждом витке эволюции<br>разработки                         | Трудности контроля и управления временем разработки |
| Включает возможность оценки системы в итерационную структуру разработки                 |                                                     |
| Использует моделирование для уменьшения риска и совершенствования программного продукта |                                                     |
P.S. Трудно определить момент перехода к следующему этапу; при отсутствии ограничений может привести к бесконечному совершенствованию системы.

## Итерационная модель

**Итерационная модель** представляет собой разработку ИС через последовательность повторяющихся циклов. Каждый цикл включает полный набор работ - от анализа требований до тестирования и поставки результата. После каждой итерации создается работоспособная версия системы или ее части, которая содержит расширенную функциональность по сравнению с предыдущей версией.

![[lifecycle_iterative.png]]

| Достоинства                                                    | Недостатки                                                                      |
| -------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| Необходимость изначального использования характеристик системы | Требования к объектам определены недостаточно четко                             |
| Пригодность для использования промежуточного продукта          | Предполагаемые скорые изменения в технологиях работ                             |
| Возможности наращивания привлекаемого персонала и средств      | Возможные текущие изменения требований к системе                                |
|                                                                | Привлечение ресурсов (средств или персонала) на длительный<br>период ограничено |
P.S. В отличие от каскадной модели, здесь допускается возврат к предыдущим этапам в рамках следующих итераций. В отличие от спиральной модели, итерационная модель не требует обязательного формального анализа рисков перед каждым циклом.
